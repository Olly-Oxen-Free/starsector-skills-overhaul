# Deep review — `collective` (2026-11-02-1235)

Scope: `src/skills_overhaul/collective/` (30 files, 1,894 lines), its 22 effect handlers in
`src/skills_overhaul/effect/handlers/collective/`, `data/config/skills_overhaul/trees/commander_collective.json`,
`data/config/settings.json` (combat plugin registration), `data/hullmods/hull_mods.csv` (Tessera Mimic),
`SkillsOverhaulModPlugin` (listener registration), `NodeApplyService.resetTransientStatics`, and
`test/skills_overhaul/collective/` (9 tests).

Build: `build.sh` hard-codes `GAME_DIR=/home/jayden-eppcohen/Games/Starsector`, which does not exist in this
container, so the full build was **not run**. The 13 API-free classes in the package plus all 9 collective tests
were compiled with `javac` and run with `-ea`: all 9 pass.

## Verdict

About a third of the Collective tree is wired to nothing, and one node helps the enemy. The three most valuable
fixes: (1) Furor Machinae and Voltaic Chain filter `DamageDealtModifier` params on `instanceof WeaponAPI`, but the
engine passes projectiles and beams, so both nodes never fire. Copy the `DamagingProjectileAPI`/`BeamAPI` unwrap from
`PrecisionStrikeListener`. (2) Every automated-ship-point grant (T0 +60, Battle Conditioning +20, Command
Hierarchy +40, Transspatial Mind +90 and ×0.75 cost) goes into a `so_automated_ship_points` dynamic stat that
nothing reads. Route the grants through `AutomatedShipPointService.registerBonus` + `AutomatedShipCapApplier`, as
`SOAutomatedPointsBonusHandler` already does. (3) Wide-Range Propagation does not check the carrier's owner, so
enemy AI-cored carriers (Remnant, derelict, Omega) get the player's fighter buff.

## Blocking

### B1. Furor Machinae and Voltaic Chain never trigger: wrong `param` type
`src/skills_overhaul/collective/SOFurorMachinaeLogic.java:22` and `src/skills_overhaul/collective/SOVoltaicChainLogic.java:23`
```java
if (!(param instanceof WeaponAPI)) return null;
```
`DamageDealtModifier.modifyDamageDealt` receives the damaging entity: a `DamagingProjectileAPI` (including
`MissileAPI`) or a `BeamAPI`, never a `WeaponAPI`. The repository already handles this correctly in
`src/skills_overhaul/pilot/systems/PrecisionStrikeListener.java:49-58`.
**Failure:** a player buys both T3/T4 nodes and fights. Every hit returns at line 22/23, so
`SOFurorMachinaeTracker.recordHit` and `ChargeStackTracker.addStack` are never called. RoF stacks stay at 0 and no
chain arc ever detonates. The listeners are still attached to every AI-cored ship each battle
(`CollectiveCombatPlugin.java:139,158`), so the cost stays and the effect is gone.
**Fix:** unwrap `DamagingProjectileAPI.getWeapon()/getSource()` and `BeamAPI.getWeapon()/getSource()` as
`PrecisionStrikeListener` does, then keep the beam/missile exclusions on the unwrapped weapon. Before re-enabling
Voltaic Chain, see A3: one stack per projectile with a 15-hit detonation of 1,000 EMP + 500 shield-piercing energy
is very strong on high-RoF ballistics.

### B2. All Collective automated-ship-point grants write to a stat nothing reads
`src/skills_overhaul/effect/handlers/collective/SOCollectiveT0Handler.java:14-16`
```java
Global.getSector().getPlayerPerson().getStats()
        .getDynamic().getStat("so_automated_ship_points")
        .modifyFlat("so_collective_t0", 60f);
```
Same pattern at `SOBattleConditioningHandler.java:16-18` (`getStat`, +20),
`src/skills_overhaul/collective/SOCommandHierarchyLogic.java:70-72` (`getMod`, +40), and
`src/skills_overhaul/collective/SOTranssspatialMindLogic.java:17,19` (`getMod`, +90 and ×0.75).
`grep -rn so_automated_ship_points src` finds only these writers. No code reads the key. The writers also split
across `getStat` (a `MutableStat`) and `getMod` (a `StatBonus`), which `DynamicStatsAPI` stores in separate maps, so
a reader of either one would still miss half the grants. The mod's real cap mechanism is
`AutomatedShipPointService.registerBonus` → `AutomatedShipCapApplier.applyToPlayerFleet()` (stamps `$autoPointsMult`;
see `src/skills_overhaul/artificer/AutomatedShipCapApplier.java:14-29`).
**Failure:** a player takes the Collective T0 and the capstone expecting 120 + 60 + 20 + 40 + 90 automated points.
The cap stays at vanilla 120, so automated ships over 120 DP still take the vanilla CR penalty.
**Fix:** replace the four writers with `AutomatedShipPointService.registerBonus(<key>, value)` /
`removeBonus` + `AutomatedShipCapApplier.applyToPlayerFleet()` (the pattern in
`src/skills_overhaul/effect/handlers/SOAutomatedPointsBonusHandler.java:14-25`). Model the ×0.75 cost multiplier
explicitly in the service or drop it.

### B3. Wide-Range Propagation buffs enemy fighters
`src/skills_overhaul/collective/SOWideRangePropagationLogic.java:20-28`
```java
for (ShipAPI ship : engine.getShips()) {
    if (!ship.isAlive()) continue;
    if (!ship.isFighter()) continue;
    ...
    ShipAPI source = ship.getWing().getSourceShip();
    if (source == null) continue;
    if (!isAICored(source)) continue;
```
No `getOwner()` check on the fighter or the source. All other Collective logic filters `getOwner() != 0`.
**Failure:** the player owns the node and fights a Remnant fleet (all captains are AI cores). Every Remnant fighter
gets +10% speed, +5% ballistic/energy damage and +10% flux capacity from the player's skill. The same happens against
derelict/Omega carriers and any NPC fleet with AI-core officers.
**Fix:** add `if (ship.getOwner() != 0 || source.getOwner() != 0) continue;`.

### B4. Assimilation is never fed: T0 passives and Transspatial Interface uses are always zero
`src/skills_overhaul/collective/AssimilationRegistry.java:32-34`
```java
public static void assimilateGamma(MemoryView mem) { mem.set(GAMMA_KEY, getGammaCount(mem) + 1); }
public static void assimilateBeta(MemoryView mem)  { mem.set(BETA_KEY,  getBetaCount(mem) + 1);  }
public static void assimilateAlpha(MemoryView mem) { mem.set(ALPHA_KEY, getAlphaCount(mem) + 1); }
```
These are the only writers of the three counters, and `grep -rn assimilat src data` outside this package finds no
caller (no rule, item, dialog or console command).
**Failure:** `CollectiveCombatPlugin.applyAssimilationPassives` (`CollectiveCombatPlugin.java:177-196`) always reads
0/0/0 and applies nothing. `TransspatialInterfaceSystem.initializeUses` (`TransspatialInterfaceSystem.java:43-48`)
always writes 0 uses. The T0 node's headline passive (CR / dissipation / damage per assimilated core) cannot be
obtained.
**Fix:** wire an assimilation sink (a rules.csv option or special-item use that consumes the core and calls
`assimilateX`), or remove the passive from the node until it exists.

## Advisory (ranked)

1. **Voltaic Conduits spawns one EMP arc per AI-cored ship every frame.** `VoltaicArcEmitter.java:48-52`
   (`float empDmg = ARC_EMP_PER_SEC * amount;` … `engine.spawnEmpArc(...)`), called from
   `CollectiveCombatPlugin.java:262-267` with no cooldown. At 60 fps that is about 60 arcs per second per ship, each
   doing about 0.4 EMP. It also rescans all ships and all missiles per source ship per frame. 10 AI ships means about
   600 arc entities per second: a frame-rate and visual-noise trap the 2026-07-07 audit already flagged. Use a
   per-ship cooldown (e.g. 0.5–1 s) and fire one arc of `ARC_EMP_PER_SEC × interval`.
2. **Lattice Defense hits its cap at 30% hard flux, not 100%.** `SOLatticeDefenseLogic.java:26` applies
   `float bonus = Math.min(hardFluxFraction, 0.30f);` but the comment at `:31` says "+30% efficiency at 100% hard
   flux". As written, the full 30% shield damage reduction is reached at 30% hard flux, a ramp 3.3× steeper than
   specced. For the specced curve use `0.30f * hardFluxFraction`.
3. **Voltaic Chain balance when B1 is fixed.** `ChargeStackTracker` adds one stack per hit and decays 0.5/s
   (`ChargeStackTracker.java:8-9`). A 10-shot/s weapon detonates about every 1.6 s: roughly 600 EMP/s + 300
   shield-piercing energy DPS per target from one gun. Consider stacking by damage amount or adding a per-pair
   cooldown. The `stacks` map is also never pruned (one entry per attacker×target pair for the whole battle).
4. **Shield Burst is near-permanent on shieldless and phase ships.** `CollectiveCombatPlugin.java:311` treats
   `ship.getShield() == null` as "exposed", so any AI-cored ship without a shield cycles 2.5 s exposed / 5 s burst
   forever: +30% all weapon damage about 67% of the time, regardless of combat state. Exclude shieldless hulls or
   require recent hull/armor damage.
5. **Knowledge and Combat Memory award per engagement, to every AI core in the fleet.**
   `CollectiveBattleEndListener.java:33-37` loops `getMembersListCopy()` (including mothballed and undeployed
   members) inside `reportPlayerEngagement`, which fires once per engagement round, including pursuits. Beating a
   lone frigate gives +10 Knowledge to every core aboard. Limit the award to members that were deployed
   (`result.getWinnerResult().getAllEverDeployedCopy()`).
6. **`KnowledgeTracker.recordKill` is never called** (`KnowledgeTracker.java:33-35`; no caller in `src`). The
   per-kill Knowledge source the tier thresholds were tuned against does not exist, so tiers advance only via B5's
   per-engagement award.
7. **Termination Protocol has no payload.** `SOTerminationProtocolLogic.java:48-49`:
   `engine.applyDamage(ship, ship.getLocation(), 999_999f, DamageType.ENERGY, 0f, true, false, ship);` damages only
   the ship itself. The node grants 1.5 s of invulnerability, then guarantees the death of any AI-cored ship below 10%
   hull that might otherwise have retreated. No explosion or damage to enemies exists, so the node is net-negative
   unless an AoE is intended. Spec text is not in the repository, so this could not be checked against intent.
8. **Command Hierarchy omits half its documented aura.** `KnowledgeTier.java:28` documents
   "+2% weapon damage and +2% flux dissipation per tier". `SOCommandHierarchyLogic.java:52-53` applies only
   ballistic/energy damage, with no flux dissipation and no missiles.
9. **Tessera Mimic likely spawns for the wrong owner or not at all.** `TesseraMimicHullMod.java:41` passes
   `ship.getOwner()` after `!ship.isAlive()`. Destroyed hulks are reassigned to the neutral owner, which is why
   `ShipAPI.getOriginalOwner()` exists. Spawning through `getFleetManager(<neutral>)` either throws (swallowed by
   `catch (Throwable t)` at `:52`) or spawns neutral drones. Use `getOriginalOwner()`. Also, `borer_drone` is a
   fighter hull, so spawning it as `FleetMemberType.SHIP` is suspect. Neither hull ID is validated at load.
   (Plausible: not verified in game.)
10. **Mind Cascade and First Strike's "automated" predicate matches fighters and drones.** `SOMindCascadeListener.java:64-71`
    picks the first `getOwner()==0` ship with `getCaptain()==null || isDefault()`. Fighters, drones and
    station modules are not excluded, so the cascade buff can land on a single fighter. `SOFirstStrikeLogic.java:78-80`
    and `CollectiveCombatPlugin.java:173-175` (`isAutomated`) have the same issue. Filter `isFighter()`/`isStationModule()`
    and use `Misc.isAutomated(ship)` for "automated hull".
11. **Uncapped multiplicative stacking of hull damage reduction and weapon damage.** Hull damage taken stacks
    Structural Integrity (×0.70–0.92, `CollectiveCombatPlugin.java:365`), Combat Memory (×0.85, `:257`) and
    Mind Cascade (×0.85, `SOMindCascadeListener.java:75`) to about ×0.51. Weapon damage stacks Assimilation +12%,
    Precision ×1.10, Memory ×1.15, Shield Burst ×1.30, First Strike +30%, Hierarchy +8% and Cascade +10%. Mixing
    `modifyMult` with `modifyPercent` makes the totals hard to reason about. Pick one convention and add a test that
    asserts the worst-case total.
12. **`TransspatialInterfaceSystem` is dead code.** No ship system in `data/` references it (comment at `:22`:
    "attached … in a future integration pass"). It still writes `$so_collective.interface_uses_remaining` every
    combat (`CollectiveCombatPlugin.java:61-64`). If it is wired, note that `isHostileLowDP` (`:132-141`) treats any
    hostile without a fleet member (dp = 0), e.g. station modules, as a valid ≤45 DP target.
13. **Knowledge is keyed on the AI core `PersonAPI` id.** `KnowledgeTracker.java:15-17`. Pulling a core and
    re-installing it creates a new person, which loses all Knowledge and orphans the old sector-memory key. Keys are
    never cleaned up.
14. **Duplicated helpers.** `isAICored` is copied verbatim into 12 classes and `isAutomated` into 3. A single
    package-private `CollectiveShips` helper would let #10 be fixed once.
15. **Per-frame allocation.** `applyAssimilationPassives` and `advanceBattleConditioning` build a new `MemoryAPIView`
    and run sector-memory lookups every frame. `advanceCombatMemory` walks fleet→faction for every enemy ship every
    frame. All are constant within a battle; compute them once in `init` or on a 1 s timer.

## Tests (ranked missing/weak behaviours)

1. No test covers the `DamageDealtModifier` param-unwrapping path (B1). Extract a pure `resolveWeapon(Object)` and
   test it with projectile, beam and missile stand-ins.
2. `CombatMemoryTrackerTest` exercises only the instance API (`CombatMemoryTracker.java:51-72`, marked "tests only").
   The persistent `recordEngagement(MemoryView, …)` that production uses, including its faction-switch zeroing at
   `:29-31`, is untested.
3. `CollectiveSmokeTest` "Test 3" (`CollectiveSmokeTest.java:20-24`) asserts inline arithmetic
   (`Math.min(10 * 1f, 10f)`) instead of calling `AssimilationRegistry`, so it can never fail.
4. No test asserts that Lattice Defense reaches its cap at 100% hard flux (A2), that Shield Burst does not trigger
   for shieldless hulls (A4), or that Wide-Range Propagation ignores non-player fighters (B3). The decision logic
   would need extracting from the `ShipAPI` loops first.
5. No test checks that every key in the tree JSON resolves to a handler that registers a node consumed by a combat
   or campaign path. Such a test would have flagged B2 and B4.

## Design notes

1. The package splits "is this node owned" (`CollectiveActiveNodes`, a JVM static re-filled on load) from
   "is the tree active" (`$so_collective.active` in sector memory). The listener gates on the memory flag and the
   combat plugin gates on the static set. Use one source of truth.
2. Most nodes apply stat mods every frame and never remove them. That works only because combat ships are
   discarded after each battle. If a buff ever moves to the campaign `FleetMemberAPI` stats, it will persist forever.
3. The pure trackers (`SOFirstStrikeTracker`, `ChargeStackTracker`, `SOFurorMachinaeTracker`) are the right shape.
   Moving the remaining decision math (Lattice, Shield Burst, Structural Integrity) into similar pure classes would
   make A2/A4 testable without the game jar.
4. `build.sh` hard-codes a single developer's home directory. Accepting `GAME_DIR` from the environment would let
   CI and review runs do a full build.
