## Verdict

Most of the arithmetic in this package is sound and tested. The defects are in the glue that runs once per battle and in the campaign baselines. The three most valuable fixes:
1. **Latch the flagship lazily in `PilotXPTracker`.** It is read once in `init`, before ships deploy. Today every battle scores the underdog multiplier against a hard-coded 10 DP, and the "first ship never died" rule for the survival bonus never fires (B1).
2. **Make battle-end detection wait for enemy reserves.** The survival bonus is paid once, the first time no enemy ship is alive. When the enemy fights in waves, it is paid at the gap between waves and the rest of the battle is ignored (B2).
3. **Count only real contribution in the survival bonus.** The pool adds the *full* XP value of every kill the player chipped. A single hit on each enemy ship is enough to collect up to 0.6× each ship's value (A1).

## Blocking

### B1: `PilotXPTracker` reads the flagship in `init()`, before deployment, and never retries
`src/skills_overhaul/xp/PilotXPTracker.java:42`
```java
        ShipAPI pf = engine.getPlayerShip();
        if (pf != null) {
            firstShipId = pf.getId();
            flagshipDP = dpOf(pf);
        }
```
`flagshipDP` defaults to `10f` (`PilotXPTracker.java:26`), and `firstShipId` is never set anywhere else. In this repository's own experience, the player ship is not available in `init`. Every sibling combat plugin defers the flagship to `advance()` and retries while it is null. `GunneryCombatPlugin.java:306-308` says so directly: `flagship = engine.getPlayerShip(); // Retry next frame: latching initialized with a null flagship killed the lane all battle.` `DefenseCombatPlugin.java:47-49` does the same. When `pf` is null at init, two things go wrong:
- **Underdog scoring:** `PilotXPMath.underdog(enemyDP, 10f, …)` is applied to every kill. A frigate flagship (about 5 DP) that kills a 10-DP destroyer gets 1.0× instead of 2.0×. A 40-DP capital that kills a 15-DP cruiser gets 1.5× instead of 0.75×. The survival "difficulty" term is skewed the same way (`PilotXPTracker.java:110`).
- **Survival rule:** `firstShipId` stays null, so the guard at `PilotXPTracker.java:82` never runs and `firstShipEverDied` stays false. If the flagship is destroyed and the player transfers command to another ship, `finalShipAlive` is true for the new ship and the survival bonus is paid. The rule this field exists to enforce is bypassed.

**Fix:** in `advance()`, latch `firstShipId` and `flagshipDP` the first time `engine.getPlayerShip()` is non-null and is not a shuttle pod. Until it has latched, skip the `firstShipEverDied` check (and arguably kill scoring too).

### B2: the survival bonus is paid at the first frame with no live enemy ship, including gaps between reinforcement waves
`src/skills_overhaul/xp/PilotXPTracker.java:88` and `:94`
```java
        if (!bonusPaid && isCombatEnding()) {
            payBattleEndBonus();
            bonusPaid = true;
        }
```
```java
        if (engine.isCombatOver()) return true;
        for (ShipAPI s : engine.getShips()) {
            if (s.getOwner() == 1 && s.isAlive()) return false;
        }
        return true;
```
`isCombatEnding()` returns true whenever no owner-1 ship is alive *on the field*. It doesn't check the enemy's reserves. Ships held back by the battle-size cap enter only after deployed ships die or retreat, so there is at least one frame with no live enemy between waves. If no enemy fighters are airborne, the bonus is paid on that frame, using only the `totalKilledXP` collected so far, and `bonusPaid` is latched. Kills in every later wave never feed the survival bonus. The check also runs on the first unpaused frame, if no enemy has spawned yet. Then it pays 0 and latches, and the battle gets no survival bonus at all.

**Fix:** treat it as victory only if `!hookedEnemyIds.isEmpty()` and `engine.getFleetManager(1).getReservesCopy().isEmpty()` and no owner-1 ship is alive. Otherwise rely on `engine.isCombatOver()`.

## Advisory

1. **The survival bonus credits the full value of any kill the player touched** (`PilotXPTracker.java:137-140`: `if (reward > 0f) { … totalKilledXP += xp; }`). `reward > 0` holds for any non-zero damage share, so a single shot counts. `survivalBonus` then pays `0.20 × Σxp × difficulty`, with difficulty up to 3.0. The strategy: tag every enemy ship once, let allies take the kills, and stay alive for 60 s. That collects up to 0.6× each ship's XP value, about a quarter of a solo kill's 2.4×, for no real contribution. Fix: accumulate `xp * weighted` (the player's share) instead of `xp`.
2. **Kill detection depends on when `isAlive()` changes** (`PilotXPTracker.java:181` and `:202`: `if (!targetShip.isAlive()) tracker.onEnemyKilled(shipId, targetShip);`). A kill counts only if the ship is already marked dead inside the callback for some damage event. If the hulk flag is set after damage listeners run, the killing blow is missed. The kill is then credited only if something hits the hulk later, and never if the hulk is left alone. Fix: in `advance()`, poll the hooked ids and call `onEnemyKilled` for any ship that is no longer alive and still has an entry in `enemyXPValue`. The existing `remove` already prevents double pay.
3. **The commander XP baseline is transient, so the amount awarded depends on reloads** (`CommanderXPListener.java:17-19` and `:45-52`). `lastSeenVanillaXP` is re-seeded from the current vanilla XP every time a save loads. Any vanilla XP gained after the last engagement and before saving is never mirrored. Without a reload, the same XP *is* mirrored at the next engagement. That includes non-combat XP (exploration, surveys, missions), which is credited to `Tree.COMMANDER`. Two players with identical play get different Commander XP depending on whether they reloaded. Fix: keep the baseline in sector memory, e.g. `$skills.commander.last_vanilla_xp`. Separately, decide whether non-combat XP should be mirrored at all.
4. **Installing mid-save grants a founding XP windfall** (`AdminXPTracker.java:110-116`). On the first economy tick, every existing player colony is new to `colony_seen` and gets `onColonyFounded`. With 5 colonies that is 1000+500+333+250+200, times the modifier. This stacks with the universal points `MigrationPlugin.runOnce` already grants. It also advances `FOUNDING_N_KEY`, so the player's first real colony after installing is worth only a sixth of the base. Fix: on the first run (when `FOUNDING_N_KEY` is absent), mark existing markets as seen without paying, or pay deliberately as part of migration.
5. **Crisis XP can't be reached in normal play** (`AdminXPTracker.java:25-30` and `:54`). `onCrisisResolved` is called only from the console helper `OrphanSkillGranter.fireCrisis`. `CRISIS_VALUES` is effectively dead content, and the tree text should not promise it.
6. **New colonies and Nex conquests are detected once a month, not per tick** (`AdminXPTracker.java:104`: `if (iterIndex != 0) return;`). Founding and conquest XP can arrive up to a month late, and the arrival ties up a month-boundary path that also carries `NexIntegration.pollForConquests`. That's acceptable, but it isn't documented.
7. **The modifier expression is duplicated** five times (`AdminXPTracker.java:36-38`, `:47-49`, `:61-63`, `:86-88` and `:95-97`), and the monthly loop computes it twice per market. Extract a `private float mod(MarketAPI m)`.
8. **Test-only defaults copy the config defaults.** `PilotXPMath.cfgDefault()` (`PilotXPMath.java:13-22`) and `AdminXPMath.modifier(boolean, boolean)` (`AdminXPMath.java:31-33`) repeat the defaults in `Config.java:34-45`. Nothing outside the tests calls them, so the tests check the copies, which can drift from what ships.
9. **Unused interface:** `AdminXPTracker` implements `ColonyInteractionListener` with four empty methods (`AdminXPTracker.java:120-123`). Drop the interface.
10. **Unverified memory keys:** vassal status depends on `"$vassal"` (`AdminXPTracker.java:129`) and conquest on `"$nex_marketCapturedBy"` (`NexIntegration.java:21`). Neither is documented here or checked against Nexerelin. If either is wrong, vassal XP or conquest XP silently never happens.

## Tests

1. **`PilotXPTracker` has no test of its battle lifecycle:** flagship latch, battle-end detection, reinforcement waves, kill crediting. Both blocking findings sit there. Lifting `isCombatEnding` and the latch into pure helpers that take a ship list or a reserve count would make them testable without the engine.
2. **`AdminXPTracker` has no tests:** monthly income and streak accrual, streak cleanup when a market is lost (the "A5 fix" at `:70-80`), no double award between founding and Nex conquest, crisis cooldown.
3. **`CommanderXPMirrorTest` is tautological:** it re-implements `delta * commanderMultiplier()` with `SkillMemory.addXP` instead of calling `reportPlayerEngagement`. Neither the baseline nor the "skip the first call" logic is tested.
4. **Missing `PilotXPMath` edge cases:** `underdog` with `flagshipDP <= 0`, the survival difficulty clamp at 0.5 and 3.0, and `finalShipAlive == false`.
5. **Missing `DamageLedger` edge cases:** `totalToShip == 0` returns 0, and fighter autopilot weighting (`fighterAuto` is never exercised).

## Design notes

1. A combat plugin has no "battle ended" callback, which is why `isCombatEnding()` has to guess. Consider paying the survival bonus from the campaign-side `reportPlayerEngagement`, with `PilotXPTracker` leaving its per-battle totals in a static holder.
2. All three XP sources keep baselines or counters that matter across sessions (`lastSeenVanillaXP`, `FOUNDING_N_KEY`, `colony_seen`). Only the commander baseline is transient. Make it consistent with the other two.
3. The admin constants (`BASE_FOUNDING_XP`, `MILITARY_BONUS`, `INCOME_RATE`, `STREAK_BASE`, `CRISIS_VALUES`) are hard-coded, while the neighbouring multipliers are configurable in `skills_overhaul.json`. Move them into the config for tuning.
4. `PilotXPTracker` gives every enemy ship an XP value of `dp * 10f` (`:64`), independent of the vanilla XP value. Document the scale against the level curve so that tuning `XPCurve` doesn't silently rebalance pilot XP.
