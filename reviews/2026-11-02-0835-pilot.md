## Verdict

The pilot lanes have four broad kinds of defect. Some buffs stay on after their condition ends. Some debuffs land on the player's own ship. Several triggers can never fire. Phase ships are detected wrongly everywhere. Together these turn several T2–T4 nodes into either permanent buffs or dead nodes. The three most valuable fixes are these:

1. **Stop target-gated buffs from sticking (B4).** Flanking (+25% damage), Dragon Slayer (+30%), Point Blank (+20%), Knife Fighter and Dead Eye all stay on once the player clears or loses their target. Target Painter's shield debuff (B5) also stays on every ship it ever painted. These are balance exploits that need no setup.
2. **Fix the self-hitting and invulnerable defense effects.** Adamantine fires its 1,500-EMP arc into the player's own flagship (B2). Unbreakable writes a flat offset onto a multiplier that starts at 1, so any big armour hit does zero or negative damage (B3). Each is a one-line fix.
3. **Fix phase detection and the dead triggers.** `isPhaseShip` checks the ship-system id, but the phase cloak is the hull's defense, not its system (B6). Phase Mastery's exit burst can never run (B1). Kill detection skips every hulk (B7). Five Systems nodes do nothing or do the wrong thing until these are fixed. Cherry-picking `5c0e092` covers most of the fixes in this review.

## Blocking

### B1. Phase Mastery exit burst can never fire
`src/skills_overhaul/pilot/systems/SystemsCombatPlugin.java:135` and `:251`
```java
        wasPhased = isPhased;
...
        if (ACTIVE_NODES.contains("so_systems_phase_mastery") && wasPhased && !isPhased) {
```
**Failure:** line 135 sets `wasPhased = isPhased` before line 251 runs, so `wasPhased && !isPhased` is always false at line 251. A player who buys Phase Mastery never gets the 300-energy / 600-EMP exit burst.
**Fix:** capture `boolean phaseExited = !isPhased && wasPhased;` before line 131 and use it at both sites. When fixing this, also retarget the arc (see B2): `:254` passes `flagship` as both the anchor and the target.

### B2. Adamantine discharge arcs into the player's own flagship
`src/skills_overhaul/pilot/defense/DefenseCombatPlugin.java:95-96`
```java
                engine.spawnEmpArc(flagship, flagship.getLocation(), flagship, flagship,
                        com.fs.starfarer.api.combat.DamageType.ENERGY, 300f, 1500f, 600f,
```
**Failure:** the fourth argument of `spawnEmpArc` is the entity the arc hits. When the buffer runs out, which by design happens while the flagship is taking heavy hull damage, the flagship takes 300 energy damage and 1,500 EMP damage. That can disable its own weapons and engines at the worst possible moment. `SystemsCombatPlugin.java:254` has the same mistake for Phase Mastery.
**Fix:** target the nearest enemy, e.g. `Misc.findClosestShipEnemyOf(flagship, flagship.getLocation(), HullSize.FIGHTER, 600f, true)`, and skip the arc when that returns null. This is what `5c0e092` does.

### B3. Unbreakable clamp makes armour hits deal zero or negative damage, and the block never expires under sustained fire
`src/skills_overhaul/pilot/defense/UnbreakableArmorListener.java:65-66` and `:81-83`
```java
            damage.getModifier().modifyFlat("so_unbreakable_clamp", -(dmgValue - allowed));
            state.startBlock();
...
        void startBlock() {
            blockRemaining = BLOCK_DURATION;
        }
```
**Failure:** `DamageAPI.getModifier()` is a multiplier with base value 1, not a damage amount. Take a cell with 100 max armour sitting at 80 (floor 50, `allowed` = 30) that is hit by a 750-damage shot. The flat offset is −720, so the modifier becomes 1 − 720 = −719. The hit deals no damage, or negative damage, to armour and hull alike, not just "stops at 50%". Separately, every hit during the 8 s block calls `startBlock()` again and resets `blockRemaining`. A cell under continuous fire therefore never reaches its 15 s cooldown and stays protected for the whole battle.
**Fix:** `damage.getModifier().modifyMult("so_unbreakable_clamp", Math.max(0f, allowed / dmgValue));`, and only call `startBlock()` when `blockRemaining == 0f`. `5c0e092` fixes the multiplier but not the refresh.

### B4. Target-gated buffs stay on after the target is cleared
- `src/skills_overhaul/pilot/maneuvering/ManeuveringCombatPlugin.java:203`:
  ```java
        if (ACTIVE_NODES.contains("so_maneuver_flanking") && flagship.getShipTarget() != null) {
  ```
- `ManeuveringCombatPlugin.java:108`:
  ```java
        if (ACTIVE_NODES.contains("so_maneuver_knife_fighter") && flagship.getShipTarget() != null) {
  ```
- `src/skills_overhaul/pilot/gunnery/GunneryCombatPlugin.java:158`:
  ```java
        if (ACTIVE_NODES.contains("so_gunnery_dragon_slayer") && flagship.getShipTarget() != null) {
  ```
- `GunneryCombatPlugin.java:173`:
  ```java
        if (ACTIVE_NODES.contains("so_gunnery_point_blank") && flagship.getShipTarget() != null) {
  ```
- `GunneryCombatPlugin.java:249`:
  ```java
        if (ACTIVE_NODES.contains("so_gunnery_dead_eye") && surgicalTarget != null) {
  ```

**Failure:** the `unmodify` calls sit in the inner `else`, which only runs while a target exists. Here is one way to trigger it. The player targets a ship from the side, so Flanking applies +25% to all three weapon types. The player then deselects, or the target dies and the engine clears it. `getShipTarget()` returns null, the block is skipped, and +25% damage applies to everything for the rest of the battle. Dragon Slayer works the same way (target a capital, deselect, keep +30%), as do Point Blank (+20% damage and +50% weapon turn rate), Knife Fighter and Dead Eye's flux discount. The buffs can be stacked this way, which is a balance exploit.
**Fix:** drop `&& getShipTarget() != null` from the outer condition and treat a null target as "condition false" inside, so the `unmodify` branch runs. `5c0e092` applies this pattern to all five.

### B5. Target Painter debuff is never removed from earlier targets, and its first sample counts the target's whole flux
`src/skills_overhaul/pilot/systems/SystemsCombatPlugin.java:189-190` and `:174`
```java
                    target.getMutableStats().getShieldDamageTakenMult()
                            .modifyMult("so_target_painter", 1f + debuff);
...
                prevTargetShieldFlux = 0f;
```
**Failure:** `so_target_painter` is never `unmodify`'d anywhere in `src/`. Switching targets resets the painter's stacks (`onTargetSwitch`), but the previous ship keeps its debuff of up to +15% shield damage taken. A player who cycles targets leaves a permanent debuff on every enemy they touch. Separately, the baseline is reset to 0, so on the first frame after a switch the target's whole current flux counts as damage. That passes the 150 threshold at once, so the first stack is free.
**Fix:** keep a `paintedTarget` field and unmodify it when the target changes or is lost. Seed `prevTargetShieldFlux` with the new target's current hard flux, not 0. `5c0e092` adds the cleanup but keeps the 0 seed.

### B6. Phase-ship detection checks the ship system, but the phase cloak is the hull's defense
`src/skills_overhaul/pilot/systems/SystemsCombatPlugin.java:351-355`, `src/skills_overhaul/pilot/maneuvering/ManeuveringCombatPlugin.java:294`, `src/skills_overhaul/pilot/systems/secondary/SODimensionalSkimmer.java:58-59`
```java
                && ship.getHullSpec().getShipSystemId() != null
                && ship.getHullSpec().getShipSystemId().contains("phase");
...
            if (flagship.getHullSpec().getShipSystemId().contains("phase")) {
...
        ShipSystemAPI sys = ship.getSystem();
        return sys != null && (sys.getId().contains("phase") || sys.getId().contains("phasecloak"));
```
**Failure:** vanilla phase ships carry the phase cloak as their defense, and their ship system is something else. So these checks miss real phase ships, and they match a non-phase hull whose system id happens to contain "phase". The effects:
- Phase Mastery (`:242-243`) never applies to a phase ship.
- Void Strike and Reactive Systems use their non-phase values or paths.
- The Untouchable's zero phase cost never applies.

Line 294 also has no null guard, unlike line 354. A flagship whose hull has no ship system throws a `NullPointerException` every frame inside `advance`, which takes the combat plugin down. I didn't reproduce this in the engine.
**Fix:** use `ship.getHullSpec().isPhase()` at all three sites. This is the vanilla idiom, and it's what `5c0e092` uses.

### B7. Kill detection skips every destroyed ship, so Kill Sync and Red Line never trigger
`src/skills_overhaul/pilot/systems/SystemsCombatPlugin.java:318-319`
```java
            if (s.getOwner() != 1 || s.isFighter()) continue;
            if (prevAliveEnemyIds.contains(s.getId()) && !s.isAlive()) {
```
**Failure:** the game reassigns a destroyed ship to the neutral owner, 100. So on the frame where `!s.isAlive()` first holds, `getOwner() != 1` is already true and the kill is skipped. `prevAliveEnemyIds` only ever holds live enemies (line 312), so the owner test adds nothing except this bug. As a result Kill Sync's cooldown refund and Red Line's stacks never fire. This depends on how the game assigns hulk ownership; the analysis matches `5c0e092`'s own comment, but I didn't reproduce it in the engine.
**Fix:** drop the owner test and keep `s.isFighter()`. `5c0e092` also changes the Kill Sync class scalar to use the flagship's hull class (`killClass(flagship)`). That is a design call; this review doesn't decide it.

## Advisory

Ranked by risk.

1. **Domain Overclock speeds up the whole battle, and the change sticks if the flagship dies.** `SODomainOverclock.java:20`: `engine.getTimeMult().modifyMult("so_domain_overclock", TIMESCALE_MULT);` speeds up every ship, enemies included. Vanilla's temporal shell changes the ship's `getTimeMult()` and divides the engine clock. Also, `SystemsCombatPlugin.java:71` (`if (flagship == null || !flagship.isAlive()) return;`) stops the secondaries from ticking once the flagship dies, so an active Overclock is never removed. The same early return leaves Stasis slows and the Flux Ghost in place. Both are fixed in `5c0e092`.
2. **Experimental Overrides secondaries can't be reached in normal play, and their input handling is exploitable.** Nothing in `src/` adds any `so_secondary_*` hullmod. The csv rows are hidden (`hull_mods.csv:3-9`). The memory key set at `SOSystemsExperimentalOverridesHandler.java:14` is never read anywhere. `so_secondary_ghost`, which `SystemsCombatPlugin.java:401` checks for, has no csv row at all, so `SOFluxGhostProjector` can't be reached even from the console. If the feature is ever wired up, three things go wrong:
   - `processInputPreCoreControls` (`:57-61`) has no node gate, unlike `advance` (`:198`). A secondary would fire but its cooldown would never tick.
   - `:61` credits Kill Sync on every keypress whether or not the secondary actually fired, so mashing R refunds the primary ship system's cooldown without limit.
   - `KEY_R` (`:45`) clashes with vanilla's default targeting key. I didn't check this against the user's current key bindings.

   `activate` should return whether it fired, and the Kill Sync credit should depend on that.
3. **Gunnery locks in a null flagship.** `GunneryCombatPlugin.java:300-305` sets `initialized = true` even when `engine.getPlayerShip()` returned null. The other three lanes return early and retry next frame (e.g. `ManeuveringCombatPlugin.java:315`). If the first unpaused frame has no player ship, the whole Gunnery lane is dead for that battle. PLAUSIBLE: it depends on when the engine first returns the player ship.
4. **The flagship is never looked up again after a command transfer.** All four lanes cache `engine.getPlayerShip()` once (`SystemsCombatPlugin.java:369`, `GunneryCombatPlugin.java:300`, `ManeuveringCombatPlugin.java:314`, `DefenseCombatPlugin.java:46`). After the player transfers command, the buffs keep applying to the old ship and the newly piloted ship gets none. `SynapticRelayService.onCommandTransfer` (`:42`) is meant to handle transfer but has no caller.
5. **Reactive Systems and Target Painter count total flux as damage.** `SystemsCombatPlugin.java:93` (`float shieldFlux = flagship.getFluxTracker().getCurrFlux();`) and `:181`. Weapon fire adds soft flux, so firing with shields up counts as "shield damage" and drains the system cooldown, and a target's own weapon fire builds Painter stacks. Use `getHardFlux()`, as `5c0e092` does.
6. **The DR cap guard reads its own previous correction.** `DefenseCombatPlugin.java:154-159`: `getModifiedValue()` includes last frame's `so_dr_cap_guard`, so the guard turns on and off on alternate frames and the 5% floor holds only half the time. Unmodify it first, then measure. This is fixed in `5c0e092`. The guard also covers only hull, not armour or shield.
7. **Adamantine's buffer absorbs nothing.** `AdamantineState.java:21` (`buffer = Math.min(maxFlux * BUFFER_FRACTION, currFlux);`) recomputes the buffer every frame before `absorbHullDamage` runs (`DefenseCombatPlugin.java:91-92`). It never prevents any damage. The discharge triggers only when a single frame's hull loss exceeds the buffer, and never at zero flux.
8. **Threat Acquisition rewards firing at nothing.** `GunneryCombatPlugin.java:79-85`: `isFiringAtTarget` is true whenever any weapon fires and any target is selected. It never checks for a hit. Firing into space builds up to +20% damage **and** 20% hull damage reduction (`:108-111`).
9. **Wolfpack counts wrecks and has no cap.** `GunneryCombatPlugin.java:279-283` has no `isAlive()` check, so friendly hulks within 1,750 units count as allies. The bonus is unbounded: `allies * 0.05f + fighters * 0.01f` gives +50% with ten escorts.
10. **The Stasis Emitter slows allies too.** `SOStasisEmitter.java:24` (`if (s == ship) continue;`) has no owner filter, so every ship within 700 units is slowed by 40%, including the player's escorts and fighters.
11. **Strike Coordination buffs every fighter, and its hull bonus does nothing.** `SystemsCombatPlugin.java:219-230` checks `isFighter()`, not the bomber wing role. `getHullBonus().modifyPercent` applied after a fighter spawns doesn't change its current or maximum hit points in combat. The bomber filter is in `5c0e092`; the hull bonus is not.
12. **Red Line's CR bonus increases the deployment cost instead.** `SystemsCombatPlugin.java:117-118` modifies `getCRPerDeploymentPercent()`, which is the CR *cost* of deploying. Raising it is a penalty, and it has no in-combat effect.
13. **EMP Specialist applies to energy damage, not EMP.** `SystemsCombatPlugin.java:207-208` adds +20% to all energy weapon damage, not EMP damage. It stacks multiplicatively with Flux Exploitation, Void Strike and the other energy bonuses.
14. **Dead hooks.** `SystemsCombatPlugin.onSystemUse()` (`:333`) has no caller, so Void Strike only triggers on phase exit and non-phase ships never get it. `BountyHunterState.getAmmoRestoredFraction()` (`:17`) has no caller, so the "ammo restore" half of Bounty Hunter doesn't exist. `ExperimentalOverridesService` has no caller.
15. **Lanes run outside the campaign.** None of the four `advance` methods checks `engine.isInCampaign()`. `ACTIVE_NODES` is static and survives a quit to the main menu, so the last save's pilot nodes apply in missions and on the title-screen battle. `5c0e092` adds the gate.
16. **Code doesn't match its comments.** Ghost Protocol says "halve phase upkeep", but `ManeuveringCombatPlugin.java:271` applies `0.10f`, a 90% cut. Weapons Discipline says "amplify existing reductions by +20%", but `GunneryCombatPlugin.java:272-273` applies a flat 0.80 to flux cost.
17. **Static `instance` fields keep the last battle alive.** `GunneryCombatPlugin.java:32` and `ManeuveringCombatPlugin.java:32` hold the previous battle's plugin, with its `ShipAPI` graph, until the next `init`. Clear them in a combat-end hook.
18. **Lead From The Front buffs may stay on after the flagship dies.** The buff is driven by an `AdvanceableListener` on the flagship (`DefenseCombatPlugin.java:54`). If listeners on a hulk stop advancing, allies keep their buffs for the rest of the battle (`LeadFromTheFrontListener.java:41-45`). PLAUSIBLE: not verified against the engine.

## Tests

Ranked by value.

1. **`UnbreakableArmorListener` has no test.** Extract the clamp into a pure function (current cell, max cell, damage → multiplier) and assert the result stays in [0,1] (B3). Assert that repeated hits during the block don't extend it.
2. **The Systems state classes have no tests.** `KillSyncTracker`, `ReactiveSystemsTracker`, `RedLineStacker`, `VoidStrikeWindow` and `TargetPainterState` are pure Java and untested, while every comparable class in the other three lanes has a test.
3. **No test catches the sticky buffs (B4, B5).** Extract each target-gated condition into a predicate that takes a nullable target (`flankingActive(target)`, `dragonSlayerBonus(target)`), and assert that a null target gives "inactive". That way a test fails if a lane can never reach its `unmodify` branch.
4. **`AdamantineStateTest` doesn't test the order the plugin actually uses.** It calls `absorbHullDamage` twice without calling `updateFlux` in between. In the plugin, `updateFlux` runs every frame first, so the test passes against behaviour the plugin never has (A7).
5. **There is no test for the phase-exit edge or for phase detection (B1, B6).** A small `PhaseEdge` helper shared by Systems and Maneuvering (`PhaseStateTracker` already exists) would make the exit event testable and remove the duplicated detection logic.
6. **The `SOSecondarySystem` lifecycle has no tests.** Cooldown, active timer, and Combat Snapshot's two-press revert can be tested with null `ShipAPI`/engine arguments for `DomainOverclock`-style subclasses.

## Design notes

1. **Lift the four lanes onto one shared context.** Each lane repeats the same flagship lookup, init latch, `ACTIVE_NODES` gating and paused/alive guards, and they already disagree on the details (A3, A4). A shared `PilotCombatContext` that looks up the player ship every frame, detects transfers, and moves the lane's modifiers to the new ship would remove that whole class of bug.
2. **Replace hand-paired `modifyMult`/`unmodify` blocks.** B4 exists because the `unmodify` call sits behind a narrower guard than the `modify` call. A helper `setMult(stat, id, boolean active, float value)`, called unconditionally every frame, can't get stuck on.
3. **Track ownership of debuffs placed on other ships.** Surgical Strikes and Twist the Knife track their previous target and clean up after it. Target Painter, Stasis Emitter and Strike Coordination don't. A small per-lane `Set<ShipAPI> touched` swept on change, and at combat end, would make this consistent.
4. **Damage multipliers stack without any bound.** Within Gunnery alone, Lock On × Threat Acquisition × Killing Machine × Berserker × Overload Hunter × Dragon Slayer × Point Blank × Twist the Knife × Wolfpack all multiply together, before Maneuvering's Crossfire, Flanking, Tactical Break and Kinetic Cooling and Systems' Void Strike. Consider adding bonuses within a lane, or a per-lane cap.
5. **Land `5c0e092`.** It sits on a 48-commit unmerged branch and already fixes most of this review. Cherry-picking it onto master, then adding the B3 refresh fix, the B5 seed fix and A2's activation-gated Kill Sync credit, is far cheaper than fixing each defect again.
