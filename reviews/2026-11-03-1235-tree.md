## Verdict

Nothing new in this area ships a bug with the current data. Every pilot and commander tree, Collective included, can be fully bought under `PrereqValidator.check`; I checked this with a fixpoint probe over the real JSON. The one live defect in this code path is already on file: no admin tree has a y=4 node, so every admin capstone is blocked forever by the tier gate (`PrereqValidator.java:44`). That is reviews/2026-11-03-0034-data.md B2, it is still on master, and it is not counted again here. The real weakness is that the loader accepts almost any structure and leaves the problems to show up at purchase time. The three most valuable fixes:

1. **Validate trees structurally in `TreeLoader.fromJSON` (A2, A3, A4).** Reject cost < 1, a missing T0, missing tiers between 0 and the highest y, self or cyclic prereqs, `atLeast` outside `1..|of|`, empty `any`/`of`, and clause objects with more than one key. That would have caught data B2 at load time, and it closes the negative-cost route that mints points.
2. **Stop treating `any`/`atLeast` refs as hard ordering edges in `PendingPurchaseTopoSort` (A1).** Two nodes that are each buyable alone, and that list each other as optional alternatives, fail as a batch with `CYCLE`, even though the UI showed both as UNLOCKABLE.
3. **Delete or fix `PrereqValidator.canPurchase` / `canPurchaseWithPending` (A5).** Nothing in `src/` calls them, they skip the tier gate, and two test files still assert on them. This is the same kind of gap as the UI B1 bypass.

## Advisory

Ranked by risk.

**A1. The topo sort turns optional prereqs into mandatory edges, so a valid batch fails with a false `CYCLE`.**
`src/skills_overhaul/tree/PendingPurchaseTopoSort.java:17-21`

```java
            for (String p : n.getReferencedPrereqIds()) {
                if (pending.contains(p)) {
                    adj.get(p).add(id);
                    inDegree.put(id, inDegree.get(id) + 1);
```

`getReferencedPrereqIds()` flattens `any` and `atLeast` into the same edge set as `all`. Probe: T0 owned; tier-1 `A` has `{"any":["B","t0"]}` and tier-1 `B` has `{"any":["A","t0"]}`. `dryRun({A})` and `dryRun({B})` each succeed. `dryRun({A,B})` returns `false CYCLE A`. `SkillTreeModel.status` checks B against `pending={A}`, so the player sees B as UNLOCKABLE, adds it, and then the commit is rejected. Also, `PurchasePlan.java:91` reports `defPending.iterator().next()` as the failing node, which need not be in any cycle, because the exception at `PendingPurchaseTopoSort.java:42` gives no members. No shipped tree has such a pair, so this is latent. The four capstone `atLeast 2 of 4` clauses have no back edges. Fix: build the order by fixpoint. Repeatedly place any batch node whose clauses hold against owned ∪ already-placed nodes, and fail with the remaining set when no node can be placed. Then `PurchasePlan` can check clauses against owned ∪ placed instead of the whole batch, and the topo sort is no longer needed to catch true `all` cycles.

**A2. A negative node cost mints points, and a zero cost makes a node free. The loader accepts both.**
`src/skills_overhaul/tree/Node.java:68`

```java
                o.optInt("cost", 1),
```

The cost then flows to `SpendService.java:41` (`int takeTL = Math.min(remaining, treePts);`) and `:67` (`SkillMemory.setPoints(mem, tree, treePts - takeTL);`). Probe: a node with `"cost": -3`, bought with 0 points, succeeds and leaves 3 points. Only tree JSON can trigger it, from this mod or from another mod merged through `getMergedJSONForMod`; the player cannot. All shipped costs are 1 to 3. Fix: reject `cost < 1` in `Node.fromJSON` or `TreeLoader.fromJSON`.

**A3. The loader accepts trees that can never be completed.**
`src/skills_overhaul/tree/TreeLoader.java:33-45` checks only that T0 has no prereqs and that every reference resolves. The probe confirmed that each of these loads without error: no T0 node; a y=5 node with no y=1..4 (the admin shape, data B2); `{"all":["A"]}` on `A`; an `A`↔`B` `all` cycle; `{"atLeast":0,...}` (always true); `{"atLeast":5,"of":[one id]}` (never true); and `{"any":[]}` (never true). Each of these shows up only as a node that stays blocked forever. `TreeLoaderRealJSONTest` asserts a T0 exists, but nothing enforces it at load. Fix: add these checks to `fromJSON` and throw `JSONException`, so the existing "Failed to load <tree>" column shows the problem.

**A4. A clause object with more than one key silently ignores the extra keys, and their references skip the unknown-id check.**
`src/skills_overhaul/tree/Prereq.java:63-68`

```java
        if (o.has("all")) {
            return new All(toStringList(o.getJSONArray("all")));
        }
        if (o.has("any")) {
```

Probe: `{"all":["t0"],"any":["nonexist"]}` loads. The `any` half is dropped, and `nonexist` never reaches the check at `TreeLoader.java:39-43`. An author who writes both keys in one object, expecting AND, gets a weaker gate. Fix: require exactly one of `all`/`any`/`atLeast`, plus `of` only with `atLeast`.

**A5. `canPurchase` and `canPurchaseWithPending` are dead in production, skip the tier gate, and are still tested as if they were real.**
`src/skills_overhaul/tree/PrereqValidator.java:9-25`. Production calls only `check` (`SkillTreeModel.java:73,139`, `PurchasePlan.java:100`). `test/skills_overhaul/level/GameSpendSnapshotTest.java:56,64` and `test/skills_overhaul/tree/PrereqValidatorTest.java:29-30` assert on `canPurchase`. The snapshot test therefore checks a function that does not apply the gate the real commit path applies. Any new caller would bring back the UI B1 bypass. Fix: delete both methods and point those tests at `check`.

**A6. One malformed index entry, or a missing index file, aborts `onApplicationLoad`.**
`src/skills_overhaul/tree/TreeLoader.java:95-96`

```java
            String key = keys.getString(i);
            try {
```

`getString` runs outside the per-tree `try`. A non-string entry throws `JSONException` out of `loadTrees`, then `TreeRegistry.load` (`:17`), then `SkillsOverhaulModPlugin.java:18`. A missing or unparsable `<tab>_index.json` fails the same way at `TreeLoader.java:81`. Either one stops the game from starting, while a bad tree file only gets logged and skipped. Fix: move `getString` inside the `try`, and make a failed index produce an empty tab with a failed marker.

**A7. The `tree` field is never checked against the file it came from.**
`src/skills_overhaul/tree/TreeLoader.java:20` reads `o.getString("tree")` and nothing compares it with `tabKey + "_" + key`. `TreeRegistry.java:47-48` derives the failed key from that field. Probe: a clashing tree named `gunnery` in the pilot tab is reported as failed key `gunnery`, and `SkillTreeView.java:205` turns that into a placeholder named `pilot_gunnery`. That is the wrong column whenever the field and the file name differ, and two files that declare the same `tree` both load. All shipped files match. Fix: in `loadTrees`, reject a tree whose `tree` differs from `tabKey + "_" + key`.

**A8. Internal state is exposed as mutable objects.**
`TreeRegistry.getTrees` returns the internal `ArrayList` (`TreeRegistry.java:65-68`; `keep` is created at `:33`). `Node.getEffects` returns the shared `JSONObject`s (`Node.java:32`), and `NodeEffectApplier`, `SkillsOverhaulCombatPlugin` and `NodeTooltipContent` iterate them. No caller mutates them today. A single `put` or `remove` in any of them would change the definition for the rest of the session. Fix: wrap the list in `Collections.unmodifiableList`, and have effect consumers treat the objects as read-only or receive copies.

**A9. Dead legacy accessors.**
In `src/`, `Node.getLane/isMerge/getParentLanes/getPrereqs` (`Node.java:42-54`) and `TreeDef.getRootNodes` (`TreeDef.java:42-47`) have no callers. `getPrereqs` is the flattened list that caused UI advisory 16 (an `any` alternative treated as required). Removing it stops that from coming back.

**A10. Every check rebuilds the owned set (minor performance cost).**
`PrereqValidator.ownedSet` (`:57-65`) and `hasAnyInPreviousTier` (`:48-55`) each scan the whole def on every `check`. `SkillTreeModel.statuses()` calls `check` and a full `dryRun` once per node, so one refresh costs about O(N²·P). With trees of about 22 nodes this is negligible. It only matters if `statuses()` ends up on a per-frame path.

## Design notes

1. Validation is split across `TreeLoader.validateCoords`, `TreeLoader.fromJSON` pass 2, the `TreeDef` constructor (coordinates) and `TreeRegistry.install` (global ids). The tier rule, the strongest structural assumption, is enforced only at purchase time. A single `TreeValidator` that returns all violations, run at load and from the tests, would keep these together.
2. The clause model (`all`/`any`/`atLeast`) is boolean, but ordering (`PendingPurchaseTopoSort`) and legacy callers (`getPrereqs`) still see a flat list of ids. Any consumer that flattens clauses is wrong for `any`. Keep clause-aware APIs only.
3. `$skills.purchased.<id>` is one global namespace, and `TreeRegistry.install` drops a whole tree on any clash. A save that owns nodes of a tree dropped later keeps flags that nothing can refund, because `RespecRunner` iterates only loaded trees. Namespacing ids per tree, or migrating, would remove this.
4. `Tree.nodeIdPrefix()` (`state/Tree.java:12-19`) returns `so_p_`/`so_c_`/`so_a_`. No shipped id uses those prefixes (`so_defense_*`, `artificer_*`, `admin_warden_*`, and so on), and nothing in `src/` calls the method any more. Delete it, or it will mislead the next filter that someone writes.
