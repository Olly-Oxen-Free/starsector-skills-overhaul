## Verdict

Most of the Zealot tree does nothing in play. The three most valuable fixes:
1. **Give the player a way to choose an Oath (B1).** Nothing in production calls `OathService.setOath`, so `ZealKillListener` returns before it awards any stacks. Combat Zeal never accrues, and every Oath-dependent branch is dead.
2. **End the Crusade when its node is removed (B3).** A respec of `zealot_t5` during an active Crusade leaves the +50 cap, the −10% damage taken and the +15% hull restore running, and also revokes the only ability that can cancel it.
3. **Implement or remove Sworn Vigilance (B2).** It costs a skill point, does nothing, and is the only path to Doctrinal Authority.

The faction-id typos (B4) are masked by B1 today, but they become live bugs as soon as B1 is fixed.

## Blocking

### B1. No code path sets the Oath, so Zeal is never earned from combat
`src/skills_overhaul/zealot/ZealKillListener.java:73-74`
```java
        Oath oath = OathService.getCurrentOath(Global.getSector().getMemoryWithoutUpdate());
        if (oath == null) return;
```
`OathService.setOath` (`OathService.java:17`, `:31`) is called only from `test/skills_overhaul/zealot/OathServiceTest.java`. `git log -S "setOath(" --all` shows that it was added in 7d83e8e and never had a production caller. No rules.csv entry, ability or handler writes `$skills.zealot.oath`.

Failure scenario: a player buys the Zealot tree and wins any number of battles. `reportPlayerEngagement` returns at :74 every time, so the stack count moves only through Heavy Detachments raids (`RaidZealListener`). The stack-scaled terms in Disciplined Gunnery, Damage Control, Reinforced Plating, Battle Line, Steelbound crit, Last Stand and Death Cheat (`ZealotCombatPlugin.java:166`, `:173`, `:205`, `:217`, `ZealotArmorCritListener.java:41`, `ZealotCombatPlugin.java:262`, `:358`) stay at or near zero. Four other features are dead as well: Hammerfall's Singularity branch (`ZealotCombatPlugin.java:153`), Tribute's Singularity doubling (`:319`), the Mandate AI-core restriction (`OathService.allowsAICoreOfficer`, which no production code calls), and the `"oath"` effect filter in `NodeEffectApplier.java:56`, which always evaluates against `null`.

Fix: add an Oath selection, such as a dialog or ability, or have the T0 base apply call `OathService.setOath`, and charge `SWAP_SP_COST` on a swap. Until that exists, either default to an Oath on T0 purchase or drop the `oath == null` early return in favour of a documented default.

### B2. `zealot_t3_sworn_vigilance` can be bought but has no effect
`data/config/skills_overhaul/trees/commander_zealot.json:239-256`
```json
      "id": "zealot_t3_sworn_vigilance",
      "name": "Sworn Vigilance",
...
          "type": "SO_zeal_combat_script",
          "node": "zealot_t3_sworn_vigilance"
```
`SOZealCombatScriptHandler.apply` adds the id to `ACTIVE_NODES`, but `ZealotCombatPlugin.applyPerShipEffects` (`ZealotCombatPlugin.java:119-133`) has no `ACTIVE_NODES.contains("zealot_t3_sworn_vigilance")` branch, and no other class reads that id. `git log -S sworn_vigilance` finds no implementation ever written.

Failure scenario: the player spends 1 SP on Sworn Vigilance and gets nothing. Because it is the only prerequisite for `zealot_t4_doctrinal_authority` (json :344-348), the player has to pay for it to reach that node.

Fix: implement the effect in `ZealotCombatPlugin`. If that is deferred, hide or zero-cost the node and repoint Doctrinal Authority's prerequisite.

### B3. Removing T5 during an active Crusade leaves its bonuses running with no way to cancel
`src/skills_overhaul/effect/handlers/SOZealotT5Handler.java:23-27`
```java
        if ("core".equals(channel)) {
            ZealotCombatPlugin.ACTIVE_NODES.remove("zealot_t5");
            Global.getSector().getMemoryWithoutUpdate().unset("$skills.zealot.t5.purchased");
            skills_overhaul.effect.AbilityGrants.revoke(skills_overhaul.zealot.CrusadeAbility.ABILITY_ID);
        }
```
None of the Crusade state is touched: `CrusadeService.K_ACTIVE`, the `"crusade"` cap bonus registered at `CrusadeAbility.java:39`, and the Crusade rival. The effects keep reading that state with no T5 gate:
- `ZealotCombatPlugin.java:48-52` (`isCrusadeVsRival` → `CrusadeRivalDR.apply`, −10% hull, armor and shield damage taken)
- `PostBattleRestoreListener.java:34-40` (+15% hull restore, plus +5% hull and CR with Mobile Arsenal)
- `ZealService.getCap` (+50 cap)

Failure scenario: the player declares a Crusade, respecs T5 to get the 3 SP back, and keeps every Crusade benefit. The cancel path in `CrusadeAbility.activateImpl` (:41-45) is unreachable because the ability is revoked. The state ends only if the rival loses all of its markets (`ZealDailyTicker.java:32-35`).

Fix: in `SOZealotT5Handler.remove` (core channel), when `CrusadeService.isActive` is true, end the Crusade (`rivalDestroyed` or `manualCancel`) and call `ZealService.unregisterCapBonus(wrapper, "crusade")`. Also gate `isCrusadeVsRival` and the `PostBattleRestoreListener` Crusade fork on `$skills.zealot.t5.purchased`, so that saves already in this state recover.

## Advisory

Ranked from most to least important.

1. **Armor and hull stat changes made mid-combat may not take effect.** Several effects modify ship stats every frame in `advance()`, after ships are spawned:
   - `getArmorBonus()`: `ZealotCombatPlugin.java:146`, `:206`, `:216`, `:270`, `:341`, `:401`
   - `getHullBonus()`: `:231`

   In Starsector the armor grid and current hitpoints are seeded when the ship is created. Raising the stat afterwards may only move the armor-floor calculation and the maximum, not the armor the cells actually hold or the ship's current HP. I could not verify this without the game jar. Check it in a sim battle: compare the ship's armor cells against its rating. If the armor isn't there, move the static bonuses (T0 armor, Reinforced Plating, Battle Line, Steelbound HP) into a hullmod's `applyEffectsBeforeShipCreation`, and write conditional ones through `ArmorGridAPI`.
2. **The global damage multipliers stack very high.** Iron Discipline applies a second damage multiplier that it labels as accuracy:
   ```java
   s.getMutableStats().getBallisticWeaponDamageMult().modifyMult("zealot_t3_iron_discipline_acc", 1f + baseBonus);
   ```
   (`ZealotCombatPlugin.java:284-285`). Combined with the RoF bonus at :282-283, that is ×1.32 to ×1.50 ballistic and energy DPS on every friendly ship. It stacks multiplicatively with Hammerfall, Avenge (up to ×1.15), Capital Doctrine (×1.15), Sanctum (×1.10) and Doctrinal Authority (×1.10). Three related mislabels:
   - The "PD" bonus at :286 modifies `getEnergyAmmoRegenMult`.
   - Capital Doctrine's `hePct` (:251, :255) applies to all ballistic damage, not only HE.
   - None of these multipliers is capped.
3. **Tribute's armor bonus has no cap** (`ZealotCombatPlugin.java:340-342`):
   ```java
   float newArmor = currentArmor + armorPct * 100f;
   o.getMutableStats().getArmorBonus().modifyFlat("zealot_t4_tribute_armor", newArmor);
   ```
   Hull repair is capped at 50% (:324) and flux at 25% (:332), but armor grows by 2.5 to 10 per kill for the whole battle. Destroying 40 frigates gives every friendly ship +100 flat armor.
4. **The Crusade can be redeclared against a dead rival, and stacks above the cap are never clamped.** When the rival loses its last market, `ZealDailyTicker.java:33-34` ends the Crusade but leaves `RivalryService.K_RIVAL` set. `CrusadeAbility.isUsable` (:57-60) then allows an immediate redeclaration with no cooldown. Each redeclaration takes another −30 reputation from the rival's allies (:31-36), and the Crusade ends again the next day. Removing the +50 cap bonus also leaves stacks above the new cap: `ZealService.addStacks` only clamps when new stacks are added, and decay is the only other thing that lowers them.
5. **Singularity features are half-wired.**
   - `ZealDailyTicker.java:25` always passes `0f` as `singularityReductionPct`, so the decay reduction is unimplemented.
   - `ZealKillListener.stacksForOathCapital` (:58) has no production caller, so the Singularity capital bonus is dead code. It is exercised only by `ZealKillListenerTest.java:25`.
6. **The day counter can collide at a leap year.** `ZealDailyTicker.monotonicDay` (:50-53) computes `getCycle() * 365 + DAY_OF_YEAR`. Day 366 of cycle N equals day 1 of cycle N+1, so one day of decay is silently skipped. This is low impact. If the calendar is Gregorian, deriving the counter from `getTimestamp()` avoids it.
7. **The first decay tick loops from day 1.** `ZealService.advanceDay` (:63-67) treats a missing `K_LAST_TICK` as day 0 and loops from day 1 to today, about 75,000 iterations at cycle 206. Each iteration calls `MemoryAPI.get` through `MemoryWrapMap`. It is cheap only because stacks start at 0; if a save ever has stacks without `K_LAST_TICK` and no recent gain, the stacks are wiped. Bootstrap `lastTick = today` instead.
8. **Capital Doctrine costs O(n²) per frame.** `ZealotCombatPlugin.java:245-248` rescans `engine.getShips()`, fighters included, once for every friendly ship on every frame. Compute the capital count once per frame in `advance()`.
9. **Zealot effects reach ships outside the player's fleet.** `ZealotCombatPlugin.java:49-54` applies every effect to every `owner == 0` ship, including allied NPC fleets and fighters. `AvengeState` (:186) also counts allied NPC losses towards Avenge. Confirm this against the spec. Most fleet-skill effects in vanilla apply only to the player's own fleet.
10. **The Nex reflection call could have large side effects.** `CrusadeNPCStub.java:57` calls `adjustRelations(faction1, faction2, -1.0f, null, null, null)` through reflection, with null `RepLevel` bounds. That sets Hegemony or the Luddic Church to full hostility with the player's rival, a major change to the world state. Any failure is caught as `Throwable` and only logged. I couldn't check the Nex signature or how it handles nulls.
11. **The Steelbound crit listener is broader than its name.** `ZealotArmorCritListener.java:40` reads sector memory on every damage event, and it doesn't filter `target`, so hits on missiles, fighters and asteroids can also crit. It has no armor-hit check beyond `!shieldHit`.
12. **There are two implementations of every memory accessor.** `OathService`, `ZealService`, `RivalryService` and `CrusadeService` each carry both `Map` and `MemoryAPI` overloads, even though `ZealDailyTicker.MemoryWrapMap` already bridges the two. The copies have already drifted:
    - `sumCapBonuses(Map)` (:55) casts with no type check.
    - `sumCapBonuses(MemoryAPI)` (:104-105) is tolerant.
    - The `MemoryAPI` variant of `addStacks` (:89-96) duplicates the `Map` one.

    Keep only the `Map` versions and wrap at the call sites.
13. **The tier-3 flag is effectively dead.** `SOZealCombatScriptHandler.java:17` writes `$so_zealot.tier_reached.3` with a `0f` expiry. As the comment at `DoctrinalAuthorityTicker.java:46-48` notes, that is cleared on the next memory advance, and nothing in the repository reads the key.

## Design notes

1. Zealot state is split across `ACTIVE_NODES` (static, rebuilt on load), `*.purchased` memory flags, and handler-specific keys. Doctrinal Authority already needed its own special gate (`ZealotCombatPlugin.java:130-133`). One "is node owned" query, like the one `NodeEffectApplier` provides, would remove that class of wiring bug (B2, B3).
2. Crusade lifecycle logic is spread across `CrusadeAbility`, `ZealDailyTicker` and `SOZealotT5Handler`. Moving declare, cancel, end and the cap-bonus bookkeeping into `CrusadeService` would keep the cap bonus and the active flag in sync by construction.
3. All of the combat effects are re-applied to every ship on every frame. Static bonuses would be cheaper as a hidden hullmod or as a one-time application on first sight of a ship, and doing it that way would also settle Advisory 1.
4. Even with B1 fixed, Zeal comes from only two sources: Oath kills and Heavy Detachments raids. The roughly 1.5–4 stacks of daily decay makes 100-stack play depend on constant combat. Check the decay curve against the expected gain once B1 lands.
