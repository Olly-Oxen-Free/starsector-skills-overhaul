## 1. Summary

Implement the 4 unimplemented and 1 silently-broken Pilot/Gunnery skill nodes so all 18 tree nodes produce their intended in-combat behavior. Pre-PRD audit miscounted the gap (claimed 15 missing); research correction shows only 5 nodes need work — the rest already function via `GunneryCombatPlugin.applyMods()`.

## 2. Vision & Why

Players currently unlock 5 gunnery nodes that have no effect: surgical, twist_knife, dead_eye, weapons_discipline, and ordnance_res (the last has param accepted but skipped at `SOPilotedStatHandler.java:78-80`). This breaks the pilot tree's value proposition. Spec at `2026-04-30-pilot-gunnery-spec.md` defines exact mechanics per node — implementation is straightforward, gated only by ammo-cap API uncertainty for ordnance_res.

## 3. Scope

### In scope
- `SO_gunnery_surgical` — +30% dmg vs WEAPON_MOUNT + ENGINE hit types (DamageListener fallback if no attacker-side API)
- `SO_gunnery_twist_knife` — target <60% hull OR retreating → +25% dmg, target −15% speed, target loses ZFB
- `SO_gunnery_dead_eye` — +10% non-missile range, perfect autofire accuracy (modifyFlat 1.0), −10% flux beyond 75% range
- `SO_gunnery_weapons_discipline` — no weapon malfunction, +20% flux reductions
- `SO_gunnery_ordnance_res` — `nonMissileAmmoCapBonus: 0.40` + `ammoRegenBonus: 0.25`
- EffectRegistry rewiring + load-time smoke test (no NoOp warnings)

### Out of scope
- Mechanic redesign / balance retuning of working nodes
- Defense/Maneuvering/Systems lane gaps (separate PRDs)
- In-game gameplay verification (success criterion is code-only per user)
- UI changes

## 4. Success Criteria

- `./build.sh` and `./build.sh test` pass clean.
- `EffectRegistry` registrations: each of the 5 ids resolves to a real handler or applyMods block (no `NoOpHandler` fallback warnings on mod load).
- For static-stat handlers: `apply()`/`remove()` use unique `nodeId` source ids and mirror unmodify on remove (no leaked stat mods on refund).
- Existing state-machine POJO tests still pass.
- New state-machine logic (if any) covered by `java -ea` POJO tests.

## 5. Risks (per user: log all three)

- **R1 — ordnance_res ammo-cap:** No direct `MutableShipStatsAPI` method for non-missile ammo cap. Spec suggests `WeaponAPI.resetAmmo()` or direct manipulation. Engine-init timing risk (fighting game's ammo init). **Mitigation:** investigation task T0 must confirm approach before T5 starts; check Second-in-Command + other reference mods for precedent.
- **R2 — modifyMult compounding:** Glass Cannon (×1.30) × Surgical (+30% dmg via listener) × any future bonus compounds multiplicatively. Document multiplier sources in handler comments.
- **R3 — onKill() wiring unverified:** `GunneryCombatPlugin.onKill()` defined at line 192 but call-site not seen by researcher. T0 must verify call-site (CombatListenerAPI or similar) before any new kill-reactive handler depends on it. (Note: none of the 5 PRD nodes are kill-reactive, so this is informational only — but should be confirmed for tree integrity.)
